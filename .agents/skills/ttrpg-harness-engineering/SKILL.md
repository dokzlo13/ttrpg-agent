# ttrpg-harness-engineering

This project is a set of capabilities that three harnesses (pi, Claude Code,
Codex) each discover differently. This skill is how that stays true over time
instead of drifting back into one harness's dialect.

## Scope boundary — read this first

**In scope:** `.agents/**`, `.pi/**`, `.claude/**`, `.codex/**`, `.mcp.json`, `AGENTS.md`,
`CLAUDE.md`, `README.md`, `.env.example`, `.gitignore`, `pytest.ini`.

**Out of scope:** `vault/`, `imports/`, `.qmd` (gone), and the *contents* of
`.cache/`. Never run an ingest, an embed, or a cleanup to "see what happens".
When a change genuinely needs live-data evidence, stop and hand off:

| Need | Hand off to |
|---|---|
| index/collection behaviour | `ttrpg-system-qmd-maintenance` |
| deleting anything at all | `ttrpg-system-data-cleanup` |
| running a book ingest | `ttrpg-import-book-pdf` |

Never print `.env` contents, `.agents/state/foundry-credentials.json`, or any
credential. Never commit user data. Never weaken the protected-path or
expensive-class lists in `ttrpg-system-data-cleanup` — those exist because the
naive repair costs 5.5 GB of re-downloads.

## Architecture invariants

Six layers, each with one owner:

```
L5  Governance      this skill
L4  Lifecycle       .agents/harness <bootstrap|doctor|sync|verify|vendor>
L3  Adapters        .claude/  .pi/  .codex/config.toml        <- GENERATED
L2  Contracts       env contract · tool contract · model tiers
L1  Canonical       .agents/{skills,prompts,chains,cli,bin,env.sh,manifest.toml}
L0  Data            vault/ imports/ .cache/                   <- NEVER TOUCHED
```

1. **`.agents/` is canonical. Adapters are outputs.** Every generated file
   carries a `GENERATED by .agents/harness sync — do not edit` header. If you
   need different behaviour in Claude, change the generator or the canonical
   source, never the emitted file. Exception: `.claude/settings.local.json` is
   user-owned and is never generated or overwritten.
2. **Correctness lives in Tier 1, never Tier 2.** `.agents/bin/<tool>` resolves
   the repo root from `BASH_SOURCE`, exports `TTRPG_ROOT`, sources
   `.agents/env.sh`, then execs. A tool invoked that way is correct with zero
   harness configuration, from any cwd, under any harness or a bare shell.
   Harness env injection (pi's `shellCommandPrefix`, Claude's `$CLAUDE_ENV_FILE`
   hook, the Codex launcher) is **ergonomics only**. If a harness breaks it
   tomorrow, only convenience regresses.
   **No skill may depend on Tier 2.** Skills reference `.agents/bin/*`.
3. **No bare tool names in skills.** Not `qmd`, not `marker_single`. A bare
   invocation runs outside the env contract and writes gigabytes into
   `~/.cache/` — that is exactly how `~/.cache/datalab` grew a 3.3 GB duplicate.
4. **One spec per tool, two surfaces.** `.agents/cli/<tool>/spec.mjs` drives both
   `cli.mjs` (argv) and `.pi/extensions/<tool>/index.ts` (typebox). Never
   hand-mirror parameters; that is a guaranteed drift source.
5. **Model tiers, not model IDs.** `openai-codex/gpt-5.6-sol` is pi routing
   syntax and is meaningless — actively harmful — in a Claude command. Declare
   tiers in `manifest.toml`; let each adapter map them.
6. **No `set -e` in `env.sh` or `.agents/bin/*`.** Several probes exit non-zero
   as normal control flow (a missing qmd collection is the state the code
   repairs; `type -aP` exits 1 when a binary is absent). Under errexit those
   abort the calling shell *silently*, on the fresh-clone path. Use
   `set -uo pipefail`.
7. **Caches are forced, not defaulted.** Every cache var in `env.sh` is
   unconditional, not `${VAR:-…}`, so an inherited shell value cannot silently
   break isolation. The one escape hatch is `TTRPG_ALLOW_HOST_CACHES=1`.
8. **No global installs, no global config.** Everything the project needs is
   project-local or is a declared Tier G prerequisite that bootstrap only
   *checks*. Codex MCP registration lives in generated `.codex/config.toml` and
   must remain absent from the user-level Codex config.

## What each harness can and cannot do

Established by running the real binaries, not from docs. Re-probe if a version
moves.

| Capability | pi 0.83 | Claude Code 2.1.220 | Codex 0.146 |
|---|---|---|---|
| `.agents/skills/` discovery | native | needs `.claude/skills/<n>` symlinks (followed) | native |
| `AGENTS.md` | yes | **no** — needs `CLAUDE.md` → `@AGENTS.md` | yes |
| Project slash prompts | `.pi/prompts/` | `.claude/commands/` | **none — user scope only** |
| Project MCP config | `.mcp.json` + `.pi/mcp.json` | `.mcp.json` + `enabledMcpjsonServers`, needs `"type": "stdio"` | generated `.codex/config.toml` |
| Project hooks | extensions | `.claude/settings.json` | **no project scope** (user-scope `~/.codex/hooks.json` exists) |
| Env injection per command | `shellCommandPrefix` | `SessionStart` → `$CLAUDE_ENV_FILE` | parent-process inheritance only |
| → shell *functions* propagate | yes | yes | **no** (fresh shell per command) |
| Parallel multi-agent | chain runner | `.claude/workflows/*.js` | no |

Consequences worth remembering:

- **MCP never sees env injection on any harness.** Servers are spawned by the
  harness itself, not its Bash tool. MCP is Tier-1-only by construction.
- **Codex gets no shell functions.** A bare `qmd` cannot work there. This is not
  a bug to fix; it is why hermetic entrypoints exist.
- **pi 0.83 drops `shellCommandPrefix` in `-p` (headless) mode** — measured, not
  inferred: even `export PROBE=1` never reaches the bash tool. Headless pi
  therefore has no Tier 2 at all.
- **`env.sh` is sourced by whatever shell the harness's Bash tool uses**, which
  is the user's login shell — frequently **zsh**, not bash. Two traps, both hit
  in practice:
  - `${var,,}`, `type -aP` and friends are bash-only. Use `tr`, and walk `PATH`
    by hand (`for dir in $PATH` does not split under zsh).
  - **Never `local path`, `fpath`, `cdpath`, `manpath` or `status` in a
    function.** In zsh the lowercase `path` is tied to `PATH`, so a
    `local path=…` silently replaces `PATH` with one directory for the whole
    dynamic extent of the call — every nested command then fails with
    "command not found".

- **fish cannot source `env.sh` at all** — it is not POSIX. It gets
  `.agents/env.fish`, which holds no logic: it transcribes
  `TTRPG_ENV_DUMP=1 bash .agents/env.sh` (a `KEY=VALUE` dump mode built for
  exactly this) and defines `qmd`/`qmd-cpu` as fish functions delegating to
  `.agents/bin/*`. **If you add a variable to `env.sh`, add it to the dump
  list** or fish silently misses it. Never port logic into `env.fish`.

  Test env.sh changes under **all three** shells — `verify` does this too:
  ```bash
  bash -c 'source ./.agents/env.sh;   qmd status | head -3'
  zsh  -c 'source ./.agents/env.sh;   qmd status | head -3'
  fish -c 'source ./.agents/env.fish; qmd status | head -3'
  ```

## Diagnose before changing

```bash
git status --short                 # is anything already dirty?
.agents/harness doctor             # Tier G probes + adapter drift + vendor pins
.agents/harness verify             # structural asserts + regenerate-and-diff
```

Then, depending on the symptom:

| Symptom | Check |
|---|---|
| a harness doesn't see a skill | `.claude/skills/<n>` symlink resolves into `.agents/skills/`; `SKILL.md` `name:` matches its directory |
| a bare `qmd` fails | expected under Codex. Under pi/Claude, check Tier 2 wiring; either way `.agents/bin/qmd` must work |
| tool works in pi, not elsewhere | it is probably reaching a pi-only tool name; skills must offer the `.agents/bin/*` form too |
| caches growing in `$HOME` | something ran outside the env contract — find the bare invocation |
| adapter diff after `sync` | someone hand-edited a generated file |

## Checks that are safe without touching user data

```bash
# every entrypoint is executable and has no `set -e`
ls -l .agents/bin/ && ! grep -l 'set -e[^u]' .agents/bin/*

# the errexit regression guard: env.sh must survive strict mode with qmd absent
env PATH=/usr/bin:/bin bash -c 'set -euo pipefail; source .agents/env.sh; echo OK'

# root resolution is not cwd-dependent
(cd /tmp && "$PWD_OF_REPO/.agents/bin/qmd" status | head -3)

# isolation: nothing may be written outside the project
STAMP=$(date -Iseconds)   # ... run something ...
find ~/.cache/huggingface ~/.cache/datalab ~/.cache/uv ~/.cache/torch ~/.npm \
     -newermt "$STAMP" 2>/dev/null | head          # must be EMPTY

# tests
uv run --project .agents/cli/book-ingest pytest
uv run --project .agents/cli/vault-sync   pytest .agents/cli/vault-sync/tests
node --test .agents/cli/vault-frontmatter/*.test.js .agents/cli/image-gen/*.test.js
```

`.agents/cli/foundry-mcp/smoke-test.sh` is **not** read-only — it can trigger a
clone plus `npm ci` and authenticates to a live Foundry world. Run it only with
a world already up, and only when asked.

## Adding things

- **A skill** — create `.agents/skills/<name>/SKILL.md` with `name:` matching the
  directory, then `.agents/harness sync` to emit the Claude symlink.
- **A prompt** — canonical body in `.agents/prompts/<name>.md`, no frontmatter;
  declare tier/effort/`skill` preload in `manifest.toml`; `sync` emits pi's
  concatenated version and Claude's `@`-import stub. Codex has no project
  prompts — document the fallback in the README instead of pretending otherwise.
- **A tool** — a directory under `.agents/cli/<tool>/` with its own
  `pyproject.toml` or `package.json` and its own isolated environment, a
  `spec.mjs` if it is agent-facing, an entry in `manifest.toml` declaring its
  `runtime`, and a `.agents/bin/<tool>` entrypoint. Never share an environment
  between tools.
- **A vendored dependency** — a `[[vendor]]` block in `manifest.toml` with an
  explicit `ref`. Fetched on first use (Tier L), never at clone time.

## Anti-patterns

- Hand-editing anything under `.claude/`, `.codex/config.toml`, or the generated parts of `.pi/`.
- Adding a pi model ID to a Claude command.
- "Just this once" using a bare `qmd`/`marker_single` in a skill.
- Making a skill depend on a harness feature only one harness has, without
  giving the others a stated path.
- Adding `.cache/` as a cleanup root to make an index reset work.
- Pre-fetching Tier L artifacts during bootstrap. A fresh clone must be usable
  without a multi-gigabyte download.
